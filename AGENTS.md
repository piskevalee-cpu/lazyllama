# LazyLlama

Bun/TypeScript OpenTUI TUI that manages one `llama-server` child process and chats over its OpenAI-compatible REST API.

## Toolchain and commands

- Use Bun; `.mise.toml` pins Bun `1.4.2`. Do not replace it with Node when running the app or OpenTUI code.
- `bun run dev` | `bun run typecheck` | `bun run build` | `bun test ./test/*.test.ts`
- Focus one suite with `bun test test/core.test.ts` or `bun test test/opentui-config.test.ts`; keep tests scoped to `./test/*.test.ts` because broader filters also discover nested dependency tests.
- `bun run install:server` is explicit-only provisioning; it downloads a release or falls back to compiling `llama.cpp/`. The app never provisions or compiles the server automatically.
- No lint, formatter, codegen, CI, or root README configuration currently exists; do not invent commands for them.

## Architecture

- `src/index.ts` is the app entrypoint: CLI parsing, boot flow, server startup, and chat wiring. `src/ui/` owns the OpenTUI renderer and screen state: `controller.ts` is the session state machine and keymap owner, `chatView.ts` composes `transcript.ts` + `prompt.ts` + `sidebar.ts`, `shell.ts` is the root chrome, and `splashView.ts`/`hubView.ts` own the pre-chat screens. `layout.ts`, `keys.ts`, and `bindings.ts` hold pure breakpoint/keymap/command logic with no OpenTUI imports.
- `src/config.ts` contains pure launch-config logic and `CONFIG_FIELDS` (tunable launch options are data-driven, and a `CONFIG_FIELD.optional` entry can be switched off, renders as `off`, and is then omitted from both the server argv and the chat request); `src/server.ts` owns the child process, readiness polling, and REST/SSE helpers; `src/installer.ts` owns provisioning; `src/models.ts` scans `models/`.
- Boot flow is splash -> model picker -> config editor -> `[ Confirm & start ]` -> chat. `--model` skips the picker and opens the editor. Empty or multiple local models are not silently auto-selected by the current code.
- Chat requests must snapshot completed history before `startAssistant()` appends its placeholder; never send the live transcript array. Empty assistant placeholders are filtered from requests. Requests pin `id_slot: 0` with `cache_prompt` and `stream_options.include_usage`; context used is `timings.cache_n + prompt_n + predicted_n` and tok/s is `timings.predicted_per_second`. Read the limit with `readNCtx` (`/props` nests it under `default_generation_settings`). Requests carry `reasoning_format` (`auto` splits model thinking into `reasoning_content` deltas, `none` keeps it inline) and the prompt is an L-shaped `Box` (left `┃` rule, `╹` corner, `▀` bottom rule) that grows from 1 to `max(6, height/3)` rows.
- `ServerManager` owns one subprocess. Binary resolution is `LAZYLLAMA_SERVER_BIN` -> installer receipt -> installer directory -> local `llama.cpp/build/bin/llama-server`; otherwise the user must run `bun run install:server`. Startup refuses to claim readiness when another healthy server is already on that host/port, and it verifies that the newly spawned child is still alive after readiness. Ctrl+C, SIGINT, SIGTERM, and SIGHUP share one idempotent shutdown path (`src/shutdown.ts`) that stops the managed server before destroying the renderer. Chat requests pin `id_slot: 0` with `cache_prompt` and `n_keep` so llama.cpp reuses conversation KV cache across turns.
- `llama.cpp/` is git-ignored reference/build source: never edit or commit it. Model blobs in `models/` are git-ignored; `models/README.md` is committed.
- Branding lives only in `src/logo.ts`; splash animation stays pure in `src/splash.ts` and width-aware for the block wordmark. `src/ui/theme.ts` is monochrome: black and white over a grey ramp (`background #000000`, `panel #0a0a0a`, `element #141414`, `border #262626`, `muted #8c8c8c`, `text`/`accent` `#ffffff`). `meter` is a three-step white-to-grey ramp and `meterTrack` the dim track, and `SidebarRow.bar` rows paint a fill that fades through that ramp instead of a flat block. Element surfaces use `theme.element`; message bubbles use `theme.panel`. The chat view is OpenCode-shaped: no header bar and no bottom status bar, only the transcript, the prompt dock, and the side panel. The pre-chat screens have no header either: `shell.footer` is the only chrome, carrying the key reference on the left and `<model> · <source> · <status>` on the right, with `hintsFor()` shortening the reference so the two never overlap. Model names come from `modelDisplayName`; full paths are abbreviated only in details.
- The side panel replaces both the old footer context readout and the fixed perf column: 42 columns wide, a flex column above 120 columns, an absolute overlay with a scrim below it, toggled with `ctrl+b`, and its preference persists in `configDir()/ui-flags.json` (`LAZYLLAMA_CONFIG_DIR` overrides that path, which is how tests stay hermetic). Context, model, server, and system sections each fold with `▸`/`▾`. Context reads `context size`, `used` and a gradient meter; Model has no `ctx` row (it belongs to Context); System uses the same meters and lists every core with its percentage. `readSlotContext` (`perf.ts`) turns a `/slots` payload into a live prompt+generated footprint, so the meter moves while the model is still working. It belongs to the chat surface only: `ChatScreen.hide()` clears the panel-active flag so the splash, model picker, and config editor own the full terminal width without touching the stored preference.
- The in-transcript `⠋ thinking` placeholder and the thought block are mutually exclusive: the placeholder disappears on the first reasoning delta, the header then carries OpenCode's Braille spinner (`⠋ thinking…` at 80ms) while the model reasons, and it becomes `▾ Thought for {duration}` only once the first content token lands. The prompt box has no animation: its left footer slot is the model name, permanently. Every message box always gets a blank row above it, so a reply never touches the previous message.
- Stopping generation closes the request: the two-step Esc (`session.interrupt`) aborts the in-flight `fetch`, and llama-server cancels the task and frees the slot when the client disconnects. There is no `/stop` endpoint to call. Interrupted answers keep their partial text and get a muted `· interrupted` suffix.

## OpenTUI/input rules

- Load the `opentui` skill for UI work. The UI is imperative `@opentui/core`; do not switch to React/Solid or another renderer unless explicitly requested.
- Mouse reporting is on by default for OpenCode parity (wheel scroll, click-to-focus, hover, copy-on-release via `copyToClipboardOSC52`, `ctrl+y`); `--no-mouse` or `LAZYLLAMA_NO_MOUSE=1` turns it off. Keyboard remains the primary interface.
- The chat prompt is a `TextareaRenderable`: plain Enter is claimed by the global keymap (`key.preventDefault()`) and committed by the orchestrator, while shift/ctrl/alt+Enter and `ctrl+j` are registered as `newline` bindings on the textarea. Do not rely on `onSubmit` from `InputRenderable`; in OpenTUI 0.5.12 it is not invoked by `InputRenderable.submit()`. Hub one-line inputs still use `InputRenderableEvents.ENTER`.
- Hub selection uses native `SelectRenderable` focus, navigation, and `ITEM_SELECTED` events. Selection indicators are disabled in favor of a custom `▸` marker. Global `KeyEvent.name` is canonical `"return"`; compatibility bindings also cover `"enter"`, `"kpenter"`, and `"linefeed"`.
- When editing an inline input, let non-Escape keys reach the focused renderable. Use `@opentui/core/testing` (`createTestRenderer`, `mockInput.pressEnter()`) for keyboard/focus tests, and always destroy the test renderer in cleanup.
- Every vertical scroller (hub editor, transcript, side panel) keeps its scrollbar on the right edge and passes `verticalScrollbarOptions` in the `ScrollBoxRenderable` **constructor**, which leaves the bar's manual-visibility flag unset so it auto-hides whenever the content fits. Assigning the same options through the property setter sets that flag and pins the bar permanently — do not do that unless a surface really wants an always-on bar.
- The chat column keeps a one-row `gap` above the prompt dock so the last message never touches the prompt, and the prompt panel is a raised `element` surface rather than the message `panel` colour.
- The chat layout math lives in `layout.ts` (`isWide` >120, `SIDEBAR_WIDTH` 42, `sidebarMode`, `promptMaxHeight`, `scrollDelta` where a "page" is half the viewport and a "half page" a quarter). The transcript is a sticky-bottom `ScrollBoxRenderable`; streaming markdown is throttled to ~30fps and flushed on completion, and finalization is asynchronous, so UI tests must sleep briefly before asserting on rendered markdown.
- Chat surfaces are frameless OpenCode-style `Box`es (panel background, single left rule, no full outer frames). The user message is the only one with a panel and accent rule; assistant turns are plain text indented 3 columns so they line up with the text inside the user's bubble, with no model-name prefix, a muted `▣ {tokens} tok · {tok/s} tok/s · thought {duration}` footer, and a collapsible `▾ Thought for {duration}` line plus body driven by `reasoning_content` deltas (`ctrl+t` toggles thinking globally). Never nest a rule inside a message: a second left rule drew a stray bar beside the header and footer. Progress uses `█`/`░` blocks and Braille activity frames through `Text` renderables, never custom ASCII frames. The splash shows only the logo (reveal + ping-pong glint, no hint text). Streaming and perf polling must not block the renderer/input loop.
- OpenTUI 0.5.12 traps to avoid: never pass `wrapMode` to a `TextRenderable`/`staticText` constructor (it measures to width 0 and paints nothing) — set it after construction; never set `flexDirection` on a `ScrollBoxRenderable` (it stacks the scrollbar under the content and steals rows); `Yoga` defaults `flexShrink` to 0, so a flex child that must yield space to a fixed-width sibling needs `flexShrink: 1` and `minWidth: 0`; setting `focusedBorderColor` at runtime calls `initializeBorder()` and turns a frameless box into a 3-row bordered one.

## Tests and scope

- `test/core.test.ts` and `test/installer.test.ts` cover pure config/model/ASCII/installer parsing and avoid network, download, and cmake paths. `test/server.test.ts` covers startup guards without spawning a real server.
  `test/ui.test.ts` covers OpenTUI keyboard/focus/mouse behavior with `@opentui/core/testing` rather than a real TTY, and points `LAZYLLAMA_CONFIG_DIR` at a fresh temp dir per test so UI toggles never touch the user's real flags or leak into the next test. `test/layout.test.ts` and `test/keys.test.ts` cover the pure breakpoint and keymap layers, including the Escape precedence chain (modal -> selection -> interrupt -> clear prompt).
- Config UI fields are data-driven through `CONFIG_FIELDS`; add new launch tunables there so hub rendering and editing stay in sync. Each field also needs a `CONFIG_GROUP_ORDER` group. The editor is one vertical column: plain arrows walk every field and action top to bottom (Shift+arrows keep native fast scroll); Tab/Shift+Tab jumps between groups and actions. Its `ScrollBoxRenderable` must stay a flex-grown row with group spacing on `contentOptions`, and the density budget is `terminalHeight - 1` because only the chrome row sits outside the editor body. Editor actions are keyboard-focusable boxes, not a flat list. Lateral arrows are context-sensitive (adjust focused values, move between Back/Save/Confirm on actions, move model selection, adjust the in-chat overlay); footer hints must match actual handling. The editor uses comfortable spacing when tall and compact density when short (`requiredEditorRows`/`selectEditorDensity`); scrolling remains only for terminals too short for compact.
